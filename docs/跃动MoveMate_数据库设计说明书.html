1 引言

1.1 编写目的

本文档是《跃动 MoveMate》软件系统的数据库设计说明书，描述系统的概念结构（ER 图）、逻辑结构（关系数据模型）、对象关系映射（ORM）以及物理存储方案。文档遵循《数据库设计说明书》国标规范文本结构，面向课程评审教师、助教与项目组开发人员，作为数据库建模与实现的依据。

2 数据库总体设计

2.1 设计目标与原则

  • 一致性：以领域模型为中心，业务实体与库表一一对应，保证各模块数据口径统一；
  • 完整性：主键、外键、唯一约束、检查约束齐备，保证数据质量；
  • 规范化：关系模式达到 3NF，消除冗余；对高频变动的处方结构使用 JSONB 适度反规范化，兼顾查询性能；
  • 可扩展：模型、知识库、工具均可替换，schema 预留扩展字段；
  • 安全：健康数据加密、最小化收集、权限分级。

2.2 数据库选型

主数据库选用 PostgreSQL 14+，并启用 pgvector 扩展，实现「业务数据 + 向量检索」一体化：

存储技术用途
业务数据库PostgreSQL用户、档案、处方、打卡、会话、知识库、日志
向量库pgvector（同库扩展）知识切片向量，供 RAG 相似度检索
缓存Redis会话缓存、热点数据、限流
对象存储OSS课件、动作图片等大文件（库中仅存 URL）

2.3 存储架构

分层数据流：业务数据（PostgreSQL）承载系统状态；领域知识经切片后以「文档元数据 + 切片向量」存于 PostgreSQL/pgvector，供 Agent 检索；会话与工具调用记录落库，支撑审计与可溯源；大文件走对象存储，库中仅存引用地址。

4.11 完整性约束与规范化

  • 实体完整性：所有表均设自增主键 id；
  • 参照完整性：外键关联 user、exercise_plan、plan_item、chat_session、knowledge_doc 等，删除采用 RESTRICT 或级联策略（如删用户级联删其处方、会话）；
  • 用户自定义完整性：role 取值约束、plan.status 状态枚举、workout_log 数值非负检查；
  • 规范化：实体关系达到 3NF；exercise_plan.fitt_vp 与 tool_log 的入出参采用 JSONB，属可控的反规范化，换取处方结构与工具日志的灵活性。

5.1 映射示例（后端实体类）

@Entity @Table(name = "exercise_plan") public class ExercisePlan { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @ManyToOne @JoinColumn(name = "user_id", nullable = false) private User user; @Column(name = "fitt_vp", columnDefinition = "jsonb") private String fittVpJson; @Column(name = "status") private String status; @Column(name = "generated_at") private LocalDateTime generatedAt; @OneToMany(mappedBy = "plan") private List<PlanItem> items; }

说明：以 Java JPA 注解为例；若后端采用 Python FastAPI + SQLAlchemy，则用 __tablename__ = "exercise_plan" 与 Column("user_id", ForeignKey("user.id")) 表达等价映射。字段命名规范保持一致。

6.2 存储与分区

  • 热数据（近 6 个月打卡、会话）常驻；历史数据按月分区归档；
  • knowledge_chunk 向量维度 1024，采用 HNSW 索引平衡召回率与速度；
  • 大文件（课件、图片）不入库，存 OSS 并记录 URL。

7 领域知识与交互记录存储设计

结合本项目领域 Agent 的特点，对三类关键数据的存储与管理方式说明如下：

7.1 领域知识（知识库）

  • 结构化组织：运动科学知识按「文档（knowledge_doc）→ 切片（knowledge_chunk）」两级存储，文档带分类（处方学/强度量化/能量代谢等）与来源；
  • 向量化：切片经嵌入模型生成 1024 维向量，存于 pgvector，供 RAG 相似度检索；
  • 出处标注：检索命中的切片信息写入 chat_message.citations，实现回答可溯源。

7.2 用户交互记录（会话）

  • 智能体对话以 chat_session（会话）+ chat_message（消息）两级存储，消息含 role、content、citations，支持多轮上下文回放；
  • 工具调用过程记入 tool_log（工具名、入参、出参），既支撑审计，也支撑后续的 Agent 行为分析。

7.3 任务执行结果（处方与追踪）

  • 任务执行结果——运动处方——以 exercise_plan（处方头）+ plan_item（训练条目）存储，FITT-VP 结构存于 jsonb；
  • 执行反馈——打卡与身体数据——存于 workout_log，随时间累积形成进度曲线，作为动态调整的依据。

8 数据安全与备份

  • 加密：密码哈希（不可逆）存储；健康敏感字段传输加密、最小化收集；
  • 权限：数据库账号分角色授权，应用侧以 JWT 鉴权 + 行级权限控制；
  • 备份：每日全量 + 增量备份，WAL 归档，保留 7 天，支持时间点恢复（PITR）；
  • 审计：tool_log 与操作日志保留，满足可溯源要求。

CREATE EXTENSION IF NOT EXISTS vector; CREATE TABLE "user" ( id BIGSERIAL PRIMARY KEY, username VARCHAR(50) UNIQUE NOT NULL, password_hash VARCHAR(255) NOT NULL, role VARCHAR(20) NOT NULL DEFAULT 'user', nickname VARCHAR(50), created_at TIMESTAMP NOT NULL DEFAULT now() ); CREATE TABLE health_profile ( id BIGSERIAL PRIMARY KEY, user_id BIGINT UNIQUE REFERENCES "user"(id) ON DELETE CASCADE, age INT, gender VARCHAR(10), height_cm NUMERIC(5,1), weight_kg NUMERIC(5,1), goal TEXT, injury_notes TEXT, parq_result TEXT ); CREATE TABLE exercise_plan ( id BIGSERIAL PRIMARY KEY, user_id BIGINT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE, fitt_vp JSONB NOT NULL, status VARCHAR(20) NOT NULL DEFAULT 'active', generated_at TIMESTAMP NOT NULL DEFAULT now() ); CREATE TABLE plan_item ( id BIGSERIAL PRIMARY KEY, plan_id BIGINT NOT NULL REFERENCES exercise_plan(id) ON DELETE CASCADE, type VARCHAR(20) NOT NULL, detail TEXT, intensity VARCHAR(50) ); CREATE TABLE workout_log ( id BIGSERIAL PRIMARY KEY, user_id BIGINT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE, plan_item_id BIGINT REFERENCES plan_item(id) ON DELETE SET NULL, weight_kg NUMERIC(5,1), note TEXT, log_at TIMESTAMP NOT NULL DEFAULT now() ); CREATE TABLE knowledge_doc ( id BIGSERIAL PRIMARY KEY, title VARCHAR(255) NOT NULL, source VARCHAR(255), category VARCHAR(50) ); CREATE TABLE knowledge_chunk ( id BIGSERIAL PRIMARY KEY, doc_id BIGINT NOT NULL REFERENCES knowledge_doc(id) ON DELETE CASCADE, content TEXT NOT NULL, embedding vector(1024) ); CREATE INDEX idx_chunk_embedding ON knowledge_chunk USING hnsw (embedding vector_cosine_ops);
