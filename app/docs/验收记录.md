## 3.1 独立窗口更新

macOS 采用原生 Cocoa 窗口和 WKWebView，提供通用架构 MoveMate.app；Windows 采用 pywebview / WinForms / WebView2。窗口内承载相同前端，后端仍仅监听回环地址。macOS 关闭应用时结束自己的后端子进程；Windows 关闭窗口时关闭服务线程。macOS 禁止向应用包写入 Python 字节码缓存，运行数据始终放在用户目录。

Windows 包保留启动.bat，并提供无控制台的启动.vbs；依赖系统 WebView2 Runtime 和 .NET Framework 4.8，附微软官方 WebView2 安装器供缺少组件时手动运行。Windows 原生窗口尚未实机验证（该结论仅指 3.1 版；3.2 已实测通过）。

macOS 独立窗口追加验证：通过系统应用入口启动 MoveMate.app，实际观察到原生标题栏、Dock 应用、完整主页，以及自检后自动显示的 API 配置弹窗。窗口中没有浏览器地址栏或标签页。修复了签名应用内 Python 写缓存造成的启动等待，内置进程使用 -B 禁用字节码缓存写入。

### 真实 DeepSeek 联调

使用用户提供的 `ds.txt` 中的真实 Key，在独立临时数据库上完成：

- `POST /api/config/save`：保存成功。
- `POST /api/chat`：返回真实中文回答，响应 `provider: "deepseek"`、`model: "deepseek-chat"`。

测试数据库在结束后删除，Key 没有写入交付包、日志或文档。DeepSeek 服务端在响应中把模型标识显示为 `deepseek-flash`，属于官方别名，不影响客户端配置。

### Windows 原生窗口实测

2026-11-21 15:13 起，在 Windows 11 x64 本机从交付目录运行 `runtime\pythonw.exe desktop_windows.py`，观察到：

- 原生窗口标题为“MoveMate 跃动”，窗口尺寸 1240×850，进程响应正常。
- 后端监听 `127.0.0.1:8765`；`/api/health` 返回 `app: "movemate"`、`version: "3.2.0"`、`database: "SQLite"`。
- 已配置 `provider: "deepseek"`、`model: "deepseek-chat"`，说明 Windows 3.2 包内的 DeepSeek 配置流程已实际走通。
- 使用 Win32 `PrintWindow` 抓取原生窗口，截图为 `docs/screenshots/native-windows.png`；画面为计划助手页，聊天内容已脱敏，窗口标题栏、侧边导航、页面标题和卡片结构可见，窗口内无浏览器地址栏。
- 同一次会话中，页面已能展示带具体训练日期和调整建议的中文回复。

结论：**Windows 11 x64 本机的原生窗口、后端监听、SQLite、DeepSeek 配置和聊天页面均已实测通过**，不再只是“页面层在 Edge 中验收”。

### 页面缩放原生桥接验证

在同一套 pywebview/Edge WebView2 环境中加载 3.2 页面，并配置 `js_api=DesktopApi()`、`zoomable=True`：

- 向页面派发 `Ctrl` + `+` 键盘事件后，页面缩放标签变为 `110%`。
- `document.documentElement.style.zoom` 为空，说明没有使用 CSS 近似缩放。
- 调用 `window.pywebview.api.get_zoom()` 返回 `{"ok":true,"percent":110}`，确认原生 `WebView2.ZoomFactor` 已更新。
- 浏览器 E2E 同时覆盖无 `pywebview` 时的 CSS 回退路径。
