# MoveMate 3.2 改进说明

日期：2026-11-21  
基线：用户提供的 `MoveMate-Windows-x64.zip`（MoveMate 3.1.0）

## 1. 对基线的判断

3.1 已经不是空壳原型：领域规则、SQLite 持久化、输入校验、风险拦截、五种模型协议和本机后端都有真实实现，38 项领域检查和 16 项后端检查可以通过。它适合作为软工课程项目的可运行基线，不需要推倒重来。

这一版优先解决“演示和验收时最容易卡住”的问题，而不是继续堆功能：

| 优先级 | 基线问题 | 影响 | 3.2 处理 |
| --- | --- | --- | --- |
| P0 | 没有 DeepSeek 专用预设，用户要自己找地址、模型名和协议格式 | 课程演示时接不上 DS API | 新增 `deepseek` 格式，默认地址和模型，配置向导默认选中 |
| P0 | 配置前在聊天框提问，配置成功后问题丢失 | 演示流程不连贯 | 暂存问题，保存配置后自动继续发送 |
| P1 | Windows 启动器复用旧进程时写死 `version == 3.0.0`，实际健康接口返回 3.1.0 | 第二次启动可能重复起服务 | 改为校验 `app == movemate` 与 `ok`，版本升级不再失效 |
| P1 | 只有领域/后端测试，没有真实页面回归 | UI 改动容易破坏主流程 | 新增 Playwright + Edge 的 17 项浏览器验收 |
| P2 | README 仍写“五种格式”“Windows 未实机验证”，与代码和交付状态不一致 | 文档不可信 | 更新 README、系统设计、验收记录，补 DeepSeek 专文 |

## 2. 实际改动

### 2.1 DeepSeek 官方 API

- `backend/ai.py` 新增 `deepseek` 格式，复用 OpenAI Chat Completions 的请求/解析逻辑。
- 预置：
  - 地址：`https://api.deepseek.com/v1`
  - 默认模型：`deepseek-chat`
  - 可选模型：`deepseek-chat`、`deepseek-reasoner`
  - Key 入口：`https://platform.deepseek.com/api_keys`
- `src/app.js` 配置向导默认选中 DeepSeek，自动填入地址和模型，增加模型候选、Key 提示和 DeepSeek 平台链接。
- 后端错误映射增加 HTTP 402“账户余额不足”，避免把 DeepSeek 的余额问题误报成网络问题。
- 支持 JSON 一键填入，格式示例见 `README.md` 和 `docs/DeepSeek接入说明.md`。

### 2.2 配置体验

- 配置前提问会暂存，保存成功后自动发送；关闭配置则放弃暂存问题。
- 保留“密钥不回传页面”“地址或格式变化必须重填 Key”的安全边界。
- 原有 OpenAI、Responses、Anthropic、Gemini、Ollama 五种格式全部保留。

### 2.3 启动与可观测性

- 健康接口新增 `app: "movemate"`，版本统一为 `3.2.0`。
- Windows 启动器不再依赖写死的 `3.0.0`，后续版本升级不会破坏进程复用。
- 保留仅监听 `127.0.0.1`、随机 token、Host/Origin 校验、请求大小限制、拒绝重定向等安全设计。

### 2.4 页面缩放

- 新增 `src/zoom.js`，统一处理 `Ctrl` + 鼠标滚轮、`Ctrl` + `+` / `-`、`Ctrl` + `0`，并同步右上角的 `− / 100% / +` 控件。
- Windows 原生窗口通过 `DesktopApi` 调用 WebView2 的 `ZoomFactor`，走浏览器原生页面缩放；`zoomable=True` 解除 pywebview 默认对 Ctrl+滚轮的拦截。
- 浏览器预览没有 pywebview 时，自动回退到 CSS `zoom`，保证同一套快捷键可用。
- 范围 80%–200%，步进 10%，使用 `localStorage` 持久化。

### 2.5 验收工具

- 新增 `tests/e2e.mjs`，使用 Playwright 1.65.1 驱动本机 Microsoft Edge。
- 测试使用独立临时数据库和本地模拟模型服务，不接触真实用户数据或真实 API Key。
- 覆盖：首次配置弹窗、DeepSeek 默认值、连接测试、保存配置、页面缩放（快捷键、Ctrl+滚轮、重置、刷新持久化）、生成计划、打卡、AI 对话、刷新持久化、390px 移动端无横向溢出。

## 3. 插件与工具决策

这是本次“还需要什么插件”的结论。

### 已经够用的 DSH 内置能力

当前 DSH 会话已经提供：

- 文件读写、目录浏览、搜索（read/write/edit/glob/grep）
- PowerShell 终端（pwsh）
- 网页搜索与网页抓取（web_search/web_fetch）
- Office 文档、表格、PPT、PDF 技能
- 子智能体与工作流

对本项目而言，这些已经覆盖源码修改、运行测试、截图验收、文档生成。不需要额外安装 DSH 的浏览器、Git 或数据库插件。

### 本次实际安装的项目级工具

| 工具 | 版本 | 用途 | 安装位置 |
| --- | --- | --- | --- |
| `playwright` | 1.65.1 | 真实 Edge 浏览器 E2E、桌面/移动端截图 | 项目 `devDependencies`，不进入运行包 |

安装命令：

```sh
npm install --save-dev playwright@1.65.1
```

没有下载 Playwright 自带的 Chromium，而是使用系统已安装的 Microsoft Edge，节省约 150MB，并更接近 Windows 用户的实际 WebView2 渲染环境。

### 为什么没有安装额外的 DSH 插件

DSH 的 `desktop` profile 由 Electron 应用独占管理，直接通过 CLI 安装插件会被拒绝；当前应用版本为 `0.2.1-rc.2`，npm 上较新的插件市场包是 `0.2.1-alpha.4`，混装 alpha 插件有破坏当前界面的风险。课程项目本身也不需要新的 DSH 运行时插件，所以这次没有改动 DSH profile。

如果后续确实需要“插件市场 / 侧边栏文件树 / 持久终端”，建议等 DSH 桌面版升级后，通过应用内插件页安装同一版本的官方插件，不要手工改 `~/.dsh/profiles/desktop`。

## 5. 建议的后续改进

按软工作业的评分点，下一步优先级建议如下：

1. **真实 DeepSeek 多轮联调**：默认模型已完成一次配置测试和一轮对话；建议再用真实 Key 跑三轮连续对话和 `deepseek-reasoner`，把截图放进验收记录。
2. **领域 Agent 的工具调用**：当前助手是“带上下文的真实问答”，还不是能调用工具的 Agent。若要拿“领域 Agent 集成”高分，可增加只读工具（读取当前计划、最近训练、规则说明），让模型通过 function calling 选择工具，并记录工具日志。
3. **管理端与多用户**：当前是单机单用户，若课程要求后台管理原型，需要补管理员角色和内容审核流程；这属于服务端方案，不应塞进本地 SQLite 单用户版。
4. **团队材料**：把系统设计、数据库设计、原型链接、分工和贡献记录补齐；这些是课程提交项，不是代码问题。
