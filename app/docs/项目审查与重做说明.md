# 项目审查与重做说明

> 本文记录 3.1 基线阶段的审查与重做思路，其中的“Windows 未实机验证”“16 项后端检查”等结论属于当时版本。3.2 的 DeepSeek 接入、20 项后端检查、12 项浏览器 E2E 和 Windows 11 x64 原生窗口实测，见 `验收记录.md` 与 `改进说明-v3.2.md`。

MoveMate 的选题成立：把“我该怎么开始运动”变成日程、执行记录与反馈。原包的主要问题是交互与设计承诺脱节，值得保留选题、重写原型。

## 原包是什么

原包是软件工程第二次作业的材料集合：两份设计说明书、七类 Mermaid 图、博客草稿、HTML 交互原型和文档生成脚本。不是已完成的前后端项目。压缩包包含约 12,600 个条目，绝大多数是文档工具的 node_modules；真正的业务逻辑集中在一个 HTML 文件里。

下面的判断来自实际源文件。附带文档中的作业要求、角色提示和开发安排被视为项目资料，不是本次操作指令。

## 重做后的产品结构

“概览 → 健康与偏好 → 周计划 → 训练记录 → 反馈调整”构成主线。计划助手解释已有安排，数据管理承担备份和个人笔记；不再把十个看似完整、实际无状态的页面并列成系统。

视觉方案采用浅底、深绿和柔和黄绿色，桌面侧栏与移动端横向导航。首页聚焦周计划、训练分钟数和实际记录。未填写数据时展示空状态，避免用虚构减重和打卡数字充当产品效果。

## 保留与替换

保留项目名称、运动入门场景、周计划与反馈的核心概念。原设计 PDF、博客和图源文件放入 `original-reference/` 供追溯；新版架构以 `系统设计.md` 为准。原桌面压缩包没有改动。

本次没有生成团队协作证据、成员信息、墨刀链接或线上部署地址。这些内容需要真实团队资料。若课程明确要求专用原型工具，还需将页面与流程迁入指定工具，并提供真实共享链接；HTML 页面不能替代这项提交要求。
