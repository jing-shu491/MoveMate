## 一、项目简介（回顾第一次作业）

**跃动 MoveMate** 是一个面向健身入门人群的**个性化运动计划智能体（Web 应用）**。它把只有运动医学门诊和私教才提供的「运动处方」，用领域知识 + 工具计算 + 流程编排，做成一个每位想动起来的人都能随时拥有的「随身处方师」。

一句话定位：让每一个想动起来、却不知道如何安全开始的人，都能拥有科学、安全、可持续的运动计划。

核心矛盾：**专业指导很贵、可及性很低**；通用大模型只会给「多运动、少吃点」的空话。领域 Agent 的用武之地正在于此。

## 二、原型设计（40%）

### 2.1 原型工具与说明

原型采用 **墨刀（Modao）/ Axure** 绘制（本博客展示为可交互 HTML 原型，交互与规则说明保持一致）。原型覆盖**用户端**与**后台管理端**两部分。

> 在线预览链接：【墨刀原型链接】（待填，需确保他人可访问）

### 2.2 用户端原型

用户端包含以下页面，核心是「用户与智能体」的交互链路：

| 页面 | 主要功能 | 交互与规则说明 |
| --- | --- | --- |
| 首页（仪表盘） | 今日训练、连续打卡、体重、目标进度 | 快捷入口直达「生成处方 / 咨询智能体 / 打卡」 |
| 健康评估 | 身体数据 + PAR-Q 安全筛查 + 禁忌 | 必填项校验；筛查勾选高风险项将引导就医并终止出计划 |
| 运动处方 | FITT-VP 结构化处方 + 出处 + 安全提示 | 处方卡片按有氧/抗阻/柔韧/进阶分块展示，标注知识依据 |
| 智能体问答 | 与「跃动处方师」多轮对话 | 回答标注出处；涉及医疗诊断一律引导就医，不越界 |
| 打卡与进度 | 打卡表单 + 体重曲线 + 周完成率 | 数据回流，作为动态调整依据 |

### 2.3 后台管理端原型

| 页面 | 主要功能 |
| --- | --- |
| 用户管理 | 用户列表、角色、状态 |
| 知识库管理 | 文档上传、切片、向量化状态 |
| Agent 配置 | 系统提示词、模型、已注册工具 |
| 内容审核 | 问答记录风险分级（医疗边界识别） |
| 数据统计 | 注册/处方/问答/知识库指标 |

### 2.4 智能体交互界面与主要任务流程

这是本项目的**核心亮点**。用户在「健康评估」页提交信息后，智能体「跃动处方师」自动执行五步任务流程，界面实时展示每一步进度：

1. **信息评估**：采集身高 / 体重 / 年龄 / 目标 / 运动史 / 禁忌；
2. **安全筛查**：PAR-Q+ 与旧伤、慢病排查，识别高风险项；
3. **知识检索**：RAG 检索运动科学知识库；
4. **数值计算**：调用工具计算 TDEE / BMI / 心率区间；
5. **处方生成**：编排生成结构化 FITT-VP 处方。

生成的处方会结合用户旧伤，给出「低冲击替代 + 护膝强化」的定制方案，并在问答界面中展示**工具调用**（如 `heart_rate_zone`）与**知识出处**（如知识库 #K-042），体现智能体如何与软件功能深度结合。

## 三、概要设计（40%）

### 3.1 系统总体架构（自顶向下分层）

系统分为**表现层 → 接口层 → 应用层 → Agent 编排层 → 数据层**五层，Agent 编排层为核心，向下统一调度领域知识与工具。

**协作图**：展示对象之间的协作关系与编号消息传递。

### 3.3 领域 Agent 集成方式

- **角色与护栏**：认证运动处方师助手；必须先筛查再出计划；严守「非医疗建议」边界；结论标注出处；
- **领域知识（RAG）**：运动科学知识结构化入库（FITT-VP、强度量化、能量代谢、安全筛查等 8 个知识域），切片向量化，检索时标注出处；
- **工具调用（Function Calling）**：`calc_tdee`、`calc_bmi`、`heart_rate_zone`、`training_volume`、`fitness_score`、`plan_generator` 六个工具；
- **任务流程**：「评估 → 筛查 → 目标 → 处方 → 打卡 → 调整」六步闭环。

## 四、数据库设计

### 4.1 ER 图

> 图：ER 图

### 4.2 关系数据模型

核心关系模式（节选）：`user`、`health_profile`、`exercise_plan`、`plan_item`、`workout_log`、`chat_session`、`chat_message`、`knowledge_doc`、`knowledge_chunk`、`action`、`tool_log`、`agent_config`，共 12 张表，关系达到 3NF，完整字段与约束见《数据库设计说明书》。

### 4.3 对象关系映射（ORM）

实体类与库表一一映射（驼峰 ↔ 下划线），如 `ExercisePlan.fittVpJson ↔ exercise_plan.fitt_vp (JSONB)`、`KnowledgeChunk.embedding ↔ knowledge_chunk.embedding (vector)`。

### 4.4 领域知识 / 交互记录 / 任务结果的存储

- **领域知识**：文档 → 切片 → 向量（pgvector），检索命中写入 `chat_message.citations`；
- **用户交互记录**：会话 + 消息 + 工具日志（`tool_log`），支持审计与溯源；
- **任务执行结果**：处方（`exercise_plan` + `plan_item`）+ 打卡反馈（`workout_log`）。
